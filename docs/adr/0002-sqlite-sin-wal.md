# SQLite con diario clásico (DELETE), no WAL

La base se abre con `journal_mode = DELETE` y `synchronous = FULL`, no con WAL, aunque WAL sea el modo recomendado habitual. El 25/11/2026 la base de desarrollo quedó ilegible por un archivo `-wal` desparejo con la base (probablemente por cierres bruscos con más de una instancia abierta sobre los mismos archivos). FitnessControl es de un solo usuario y escribe poco, así que la ventaja de WAL (lectores y escritor en paralelo) no aporta nada. En cambio, el modo clásico deja la base como un único archivo, sin `-wal`/`-shm` al lado que un cierre brusco, OneDrive o un antivirus puedan separar. Se suma un candado de instancia única y un `quick_check` al abrir: si la base no está sana, la app ofrece restaurar una copia en vez de seguir.
